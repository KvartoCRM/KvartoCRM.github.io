# KvartoCRM: закрытый облачный офис риелтора

## Продуктовая модель

KvartoCRM — закрытый рабочий офис владельца CRM без публичных кабинетов клиентов. Вход выполняется по email и паролю через Supabase Auth, а данные доступны с любого устройства после авторизации.

Supabase является единственным источником правды:

- PostgreSQL хранит клиентов, объекты, задачи, события, сделки, историю касаний и импорт;
- Storage хранит фотографии и документы в приватных bucket;
- Row Level Security закрывает все записи от неавторизованных пользователей;
- фронтенд может быть опубликован как статическое Vite-приложение без собственного сервера.

KvartoCRM устанавливается как PWA: после публикации браузер создаёт обычный ярлык на рабочем столе и в меню «Пуск», а CRM запускается отдельным окном без терминала. В контекстном меню ярлыка доступны быстрые переходы к рабочему столу, объектам, контактам и задачам.

## Целевые модули

1. **Рабочий стол** — дела на сегодня, просрочки, следующие касания, новые лиды, активные объекты и быстрые действия.
2. **Контакты 360°** — собственники и покупатели, телефоны, источники, интересы, история звонков/сообщений/встреч, документы и заметки.
3. **Объекты** — карточка недвижимости, параметры, собственник, стоимость, статус, фотографии, документы, история продвижения.
4. **Воронка** — холодный → тёплый → встреча → договор → показ → сделка; отдельные причины отказов и потерянных лидов.
5. **Подбор покупателю** — требования, список подходящих объектов, исключения, отправленные варианты и реакция клиента.
6. **Календарь и задачи** — звонки, встречи, показы, дедлайны и повторные касания.
7. **Сделки** — участники, объект, этап, сумма, комиссия, документы и чек-лист.
8. **Файлы и медиа** — приватное хранение фотографий и документов в Supabase Storage.
9. **Аналитика** — конверсия по источникам, звонкам и этапам, активность, прогноз комиссии и причины потерь.
10. **Импорт** — Google Sheets/CSV с предварительным просмотром, нормализацией и защитой от дублей.

## Темы интерфейса

Оформление хранится локально на устройстве и переключается без перезагрузки:

- **Lumi Light** — нейтральный светлый режим для дневной работы;
- **Midnight** — основная тёмно-синяя тема в стиле аналитического дашборда;
- **Aurora** — тёмная бирюзово-фиолетовая тема;
- **Graphite** — строгий монохромный режим с минимальным количеством цвета;
- **Warm Sand** — светлая тёплая тема с винно-терракотовыми акцентами.

Все темы используют единые дизайн-токены для фона, панелей, границ, текста, акцентов и графиков. Это позволяет добавлять новые палитры без копирования компонентов.

- [x] восстановить сборку и статический анализ;
- [x] удалить двойную модель данных Zustand/Supabase;
- [x] расширить SQL-схему сущностями активностей, импорта и файлов;
- [x] сделать дашборд облачным;
- [x] перенести исходные Google-таблицы: 29 строк, 10 клиентов, 6 объектов, 12 задач, 4 встречи и 17 касаний;
- [x] создать Supabase-проект, приватные Storage-bucket и учётную запись владельца;
- [x] добавить устанавливаемое PWA-приложение, offline app-shell и восстановление пароля.

### Этап 2. CRM-ядро

- единая карточка клиента;
- таймлайн касаний;
- полноценная карточка объекта;
- воронка и повторные касания;
- приватная загрузка фото и документов.

### Этап 3. Продажи и автоматизация

- сделки и чек-листы;
- подбор объектов;
- напоминания и просрочки;
- фильтры, сохранённые представления и глобальный поиск;
- аналитический дашборд.

### Этап 4. Публикация

- создать приватный GitHub-репозиторий;
- настроить GitHub Actions;
- публиковать фронтенд в GitHub Pages или Cloudflare Pages;
- использовать бесплатный адрес вида `username.github.io/lumicrm` или `lumicrm.pages.dev`;
- оставить Supabase URL и anon key в клиенте, но защищать данные RLS-политиками;
- проверить мобильную версию, маршрутизацию SPA и резервное копирование.

Публикация выполняется после завершения CRM-ядра и приёмочной проверки. После появления постоянного HTTPS-адреса он задаётся как Site URL в Supabase, затем владельцу отправляется свежая ссылка для создания окончательного пароля.

Cloudflare Pages удобнее для SPA-маршрутов и даёт более короткий бесплатный поддомен. GitHub Pages тоже подходит, если добавить SPA fallback и корректный `base` в Vite.

## Импорт исходной таблицы

Исходный документ содержит листы `Холодные звонки`, `Тёпые звонки`, `Входящие звонки`, `Встречи`, `Планирование` и `Подбор`.

Строки раскладываются по CRM-сущностям:

- собственник/покупатель → `clients`;
- адрес и параметры квартиры → `properties`;
- звонок, сообщение, повторное касание → `crm_activities`;
- встреча → `events` и `crm_activities`;
- планирование → `tasks`;
- исходная строка и её fingerprint → `crm_import_rows`.

Повторный запуск импортера пропускает уже перенесённые строки по fingerprint.
