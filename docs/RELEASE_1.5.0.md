# KvartoCRM 1.5.0

## Изменения

- Календарь: день, неделя, список; длительность, часовой пояс, проверка пересечений и поиск ближайшего свободного времени. На телефоне начальный вид — день.
- Итог встречи: реакция покупателя, комментарий, следующий звонок. Запись результата и создание звонка выполняются одной транзакцией.
- После звонка можно назначить звонок или встречу. На телефоне контекст клиента открывается в отдельной панели.
- Контакты: предупреждение о совпадающем телефоне, предпросмотр объединения, журнал и отмена. Отмена блокируется, если связанные записи после объединения изменились.
- Подборки: сравнение с пожеланиями, решения и заметки по объектам, ссылка на 1/3/7 дней, отзыв ссылки, ответ покупателя. Публичный ответ содержит только явно разрешённые поля объектов.
- Сделки: доска/список, ответственный, следующий шаг и срок, подтверждение смены этапа с проверкой версии записи.
- Фильтры контактов без следующего контакта и объектов без встреч в календаре; условия доступны в существующих сохранённых представлениях.
- Формы используют общие цвета темы. Заметка в мобильной подборке занимает отдельную строку.

## Резервное копирование

Новый формат — TAR с workspace.json, фактическими файлами и манифестом SHA-256. Старые JSON-копии читаются по-прежнему. Архив не создаётся, если не получен хотя бы один файл, превышен лимит или записи изменились во время выгрузки. Служебные очереди уведомлений и подписки устройств не копируются в новый аккаунт.

Перед записью проверяются идентификаторы и ссылки между таблицами. При переносе в другой аккаунт идентификаторы меняются детерминированно, профиль назначения сохраняется, старые публичные ссылки отключаются. Сначала восстанавливаются задачи, затем родительские связи. Записи и файлы можно повторно импортировать после обрыва без создания новых идентификаторов. Запись подтверждается сервером; частичные ошибки показываются отдельно. Списки приложения обновляются после восстановления.

Лимиты: TAR 512 МиБ, JSON-раздел 50 МиБ, манифест 1 МиБ. Журнал объединений включён в архив как история для просмотра; чужой журнал не импортируется в привилегированную таблицу, отменить старое объединение в новом аккаунте нельзя. Восстановление большого архива выполняется поэтапно и не является одной общей транзакцией. При сбое нужно повторить тот же архив. Сохранённые в старом JSON ссылки могут истечь; TAR от этого не зависит.

## База

Нужны четыре миграции 2026103001, 2026103002, 2026110201, 2026110202. Единый файл: supabase/releases/20261102_update.sql. Он применён владельцем до публикации; повторный запуск не требуется.

Проверка рабочего API: новые столбцы events доступны запросу с limit=0; read_selection_share для несуществующей ссылки возвращает null; анонимное чтение contact_merge_log запрещено (42501). Эта проверка не читала пользовательские записи.

## Проверки

- npm test: 133 теста плюс 2 предварительных проверки обзора.
- npm run test:security: проверки границ аккаунтов, прав функций, публичных ссылок, шлюза, Service Worker; аудит зависимостей без уязвимостей.
- npm run test:update-db: применение единого пакета в изолированном PostgreSQL/PGlite, транзакционность результата встречи, повтор операции, отзыв публичной ссылки, объединение/отмена, запрет отмены после новых изменений, запрет прямой записи журнала.
- npm run lint; npm run build; проверка адресов production-сборки.
- Браузер: сохранение звонка, черновик, ошибка и повтор, календарный конфликт/свободное время, итог встречи, подборка/ссылка/ответ, этап сделки и предпросмотр объединения.
- 60 проверок форм (6 форм × 5 тем × 2 ширины) и 60 проверок новых экранов (4 экрана × 5 тем × 390/768/1440).
- Реальный предоставленный JSON: ошибка порядка задач воспроизведена; 30 задач и 4 связи восстановлены в изолированной базе, повтор без дубликатов. Проверенные ссылки на записи целы.
- Браузерный экспорт/импорт: принудительный серверный лимит 10 строк, 100 тестовых вложений, прерывание импорта и сбой загрузки файла, повторное восстановление, неизменность исходного аккаунта.
- Все 100 ссылок исходной пользовательской копии отвечали HTTP 200. Отдельно создан TAR с реальными 100 файлами и проверен чтением манифеста и SHA-256. Пользовательские файлы не включены в репозиторий.

Повторяемый браузерный тест: scripts/qa-backup-browser.mjs. Требуется локальный Vite на 127.0.0.1:5173 и Playwright с Edge. При необходимости PLAYWRIGHT_MODULE указывает file:-URL установленного модуля. Без аргумента используются синтетические данные; необязательный аргумент — путь к частному JSON. Внешние API в этом тесте заменены локальными ответами.

Ограничения проверки: полноценный импорт в живой второй аккаунт и установка на физический Android не выполнялись. Локальные проверки и успешная сборка установщика не заменяют эти проверки.
